## 0. 一页结论

**BempDiff 当前的主要矛盾，已经从“有没有分析能力”转为“能力有没有被看见、被使用、被审计”。**

三条判断：

1. **后端能力比 UI 呈现领先一个身位。** `FR-001`～`FR-015` 在代码中均已落地基础版：AST 归一化、API 兼容性静态分级、影响面静态分析、CI JSON 与退出码、4 套语法主题、逐 hunk 已审阅标记、树/差异虚拟滚动都已存在。下一阶段不应继续重复“加分析器”，而应把这些能力产品化。
2. **最大的体验缺口在“入口、审阅、总览”三处。** 当前是“顶部工具栏输入路径 → 三栏 diff”；缺独立启动台、缺文件级审阅进度、缺总览页、缺命令面板、缺 diff minimap。用户第一次进入时，看到的是路径输入框和十几个图标，而不是“这次发布要审什么、先看哪里、还差多少”。
3. **主题升级不是“再加一个暗色”。** 当前已有亮/暗/跟随系统、6 个强调色、4 套代码语法主题；真正的缺口是 **主题 token 体系、高对比/色盲友好、密度/字号、主题预览与导入导出、报告/安装器同主题、首屏无闪白**。

**三条主线（按优先级）：**

| 主线 | 一句话目标 | 代表需求 |
|---|---|---|
| A. 审阅驾驶舱 | 让“比对结果”变成“可签字交付的审阅结论” | 启动台、审阅进度、书签/备注、总览、报告模板 |
| B. 能力显性化 | 把已有 API 兼容/影响面/AST/CI 能力搬到界面和交付物 | 兼容性面板、影响面面板、AST 降噪提示、CI 契约 |
| C. 设计系统与主题 | 把“能看”升级为“看得久、看得准、看得一致” | Token 体系、6 主题、色盲安全、密度、主题工作室 |

**明确不做（本阶段）：**

- 不做三路合并、文件夹同步、通用图片/十六进制/媒体对比矩阵；这些会稀释“构建包审计 + 合规证据”的垂直定位。
- 不做通用 Git 客户端、通用逆向编辑器；BempDiff 的边界是“Java 构建产物 + 反编译 + 私有化合规 + 可解释 AI”。
- 不先做多窗口/云协作/账号体系；先把单机审阅闭环做扎实。

### 1.2 五个确定性趋势

**趋势 1：从“文件 diff”升级为“审阅工作流”。**

GitHub Desktop 3.5.1 支持按状态过滤变更文件；sem 直接提供 `sem certify` 输出“哪些实体改了、哪些调用方没改、哪些测试覆盖”；jar-analyzer 提供书签、备忘录、调用链。用户要的不是“看到差异”，而是“看完、标记、解释、签字”。

**趋势 2：“总览先行、细节按需下钻”。**

Diffuse 先给压缩/未压缩总量与 DEX 结构统计，再列具体 strings/methods；Beyond Compare 5 把 Home 视图和 Session 作为主入口；GitHub Desktop 3.5.9 专门修长变更列表渲染与滚动同步。BempDiff 当前是“直接进三栏”，缺少“这次变更有多大、风险在哪、先看哪 5 个文件”的总览层。

**趋势 3：主题系统是产品质量，不是皮肤。**

WinMerge 2.16.51 才引入 dark mode，随后补“暗色打开白闪”、颜色方案保存（INI，可共享/复用）、VS Dark/Solarized Dark；Beyond Compare 5 把 dark mode 做到主界面和安装器，并持续修高 DPI、字体跳变、主题预览取消不还原；delta 支持 20+ 可样式化元素与自动亮暗检测。结论：**只换 body 背景不叫主题；主题要覆盖语法、diff 语义色、边框、gutter、状态栏、报告、安装器，并能预览/保存/恢复。**

**趋势 4：“确定性语义 + AI”成为分水岭。**

japicmp 用 javassist 做二进制/源码兼容与语义版本；sem 用 tree-sitter 做实体级 diff + impact；jar-analyzer 强调“AI 有幻觉，安全审计需要确定性”，同时提供 AI 与 MCP。BempDiff 已有两阶段 AI、API 兼容、影响面静态分析，正确的方向是 **AI 消费确定性实体图与兼容性结论**，而不是让模型直接读全文猜。

**趋势 5：CLI/CI 与 Agent 接口成为桌面工具的“第二形态”。**

japicmp 已有 MCP Server；jar-analyzer 6.0 内置 MCP（SSE/Streamable HTTP）；sem 提供 `sem mcp` 与 JSON/Markdown 输出；BempDiff 已有 `ci --json --fail-on-diff`，但缺 schema 文档、SARIF、Action 模板和 Agent 接口。下一阶段应把“桌面结论”与“CI/Agent 结论”做成同一套契约。

### 2.2 当前已产品化的体验底座

这些是优势，不应在新需求里重复“建设”：

- **三栏布局**：`DiffTree`（默认 300px）+ `DiffView` + `InfoPanel`（默认 380px），左右可拖拽、可收起、专注模式。
- **差异视图**：并排/统一、行/词/字符三级、折叠未变、上/下一处、查找、自动换行、行号、语法高亮、虚拟滚动、60k 行降级简洁视图。
- **文件标签**：多 tab、pin、关闭其他/全部、右键菜单、中键关闭。
- **差异树**：按层 L0/L1/L2 分组、状态过滤、风险过滤、搜索/正则、按风险排序、右键排除/忽略/属性、虚拟滚动。
- **会话**：自动历史 + 命名会话 + 路径前进/后退。
- **报告与导出**：Markdown/HTML 报告、JAR/CLASS/全量导出、下载管理器。
- **AI**：两阶段分析、风险分类、成本闸门、流式控制台、多类别并行、可中断。
- **主题**：亮/暗/跟随系统、6 个强调色、4 套代码语法主题、暗色切换白底修复。
- **审阅**：逐 hunk “已审阅”标记，按 job+file 持久化到 localStorage。
- **性能**：DiffTree 虚拟滚动；DiffView 窗口化渲染；>60k 行自动降级。

### 2.3 当前最大问题：强能力“藏在后端/报告里”

| 能力 | 后端/内核 | 当前 UI 露出 | 产品化机会 |
|---|---|---|---|
| API 兼容性 | `ApiCompat.java` 已输出三级变更、Markdown 章节、AI 上下文 | 只在报告“API 兼容性分级”章节；无独立面板、无筛选、无跳转 | 右栏新增“兼容性”页签；文件树加 breaking 徽标；CI `--fail-on-breaking` |

## 3. 七条差距带

### 差距 1：入口与任务组织

**现状**：打开即进入工作区；路径输入、历史、会话都挤在顶部工具栏；没有“最近对比/收藏/模板/示例包”的首页。

**竞品证据**：Beyond Compare 5 把 Home 视图和 Session 作为主入口；GitHub Desktop 3.5.1 支持按状态过滤变更文件；Meld 以会话/版本控制状态组织工作。

**方向**：Launchpad + Workspace 双态。Launchpad 负责“新建/最近/收藏/模板/批量”，Workspace 负责“审阅当前任务”。

### 差距 2：审阅闭环与证据链

**现状**：已有逐 hunk 已审阅标记，但没有文件级汇总、没有“只看未审”、没有备注/书签、没有审计导出；标记只存 localStorage，不能作为团队证据。

**竞品证据**：sem 的 `certify` 输出“哪些实体改了、哪些调用方没改、哪些测试覆盖”；jar-analyzer 有书签/备忘录；GitHub PR review 有 viewed/progress。

**方向**：把“已审阅”从个人记忆升级为“审阅记录”：文件级进度、未审筛选、备注、证据摘录、报告附审阅清单、可选签名/导出。

### 差距 3：总览与导航

**现状**：状态栏有 added/deleted/modified 统计；右栏有 file/global/break/audit/console，但没有“总览页”；DiffView 有虚拟滚动，但没有 minimap/location pane。

**竞品证据**：Diffuse 先总览后明细；Beyond Compare/WinMerge 有 Location Pane；Meld 有 change block 导航；delta 有 n/N 跳转。

**方向**：新增“总览”页签（KPI + Top 风险 + 类型分布 + 建议回归）；DiffView 增加 minimap/hunk 导航条；状态栏增加审阅进度与后台任务。

### 差距 4：功能纵深

**现状**：已有 AST 归一化、源码级 API 分级、类级影响面、CI JSON；但缺二进制级 API 细节、方法级调用图、配置语义 diff、SBOM/CVE、签名校验、多反编译器、字节码视图、归档格式扩展、Office 单元格级 diff。

**竞品证据**：japicmp 的 binary/source + semantic version；sem 的实体/impact/tests；jar-analyzer 的调用链/SCA/MCP；diffoscope 的递归归档；graphtage 的结构化数据 diff。

**方向**：按“银行发布审计”的价值排序：**API 兼容 2.0 → 影响面 2.0 → 配置语义 diff → SBOM/CVE → 签名校验 → 多反编译/字节码 → 归档扩展**。

### 差距 5：UI 系统与信息密度

**现状**：顶部工具栏单行承载输入类型、历史、两个路径输入（每个 320–420px）、向上/后退/前进、比对、报告、AI、分类、导出、配置、主题、强调色等 14+ 控件；1280px 以下靠 flex-wrap 换行，视觉重心分散。

**竞品证据**：GitHub Desktop 3.5.13-beta4 专门修“工具栏可用空间计算/按钮顺序”；Beyond Compare 5 用 Home 视图分流；WinMerge 2.16.59 按活动窗口重建工具栏按钮。

**方向**：**命令栏 + 上下文操作栏**，而不是继续往工具栏塞按钮。全局高频只留“比对/停止/搜索/命令面板”，其余进 `Ctrl+Shift+P` 命令面板或“更多”。

### 差距 6：主题系统

**现状**：3 个 UI 模式（亮/暗/跟随系统）+ 6 个强调色 + 4 个代码语法主题；没有高对比、色盲安全、密度/字号/行高、主题预览/导入导出、报告/安装器主题；UI 仍直接依赖 Bootstrap 变量。

**竞品证据**：WinMerge 颜色方案可保存为 INI、内置 VS Dark/Solarized Dark、修暗色白闪；Beyond Compare 5 暗色安装器、主题预览取消还原、高 DPI 字体/对话框修复；delta 20+ 可样式化元素、自动亮暗检测；jar-analyzer 3 主题 10 风格。

**方向**：CSS 变量 + Theme Registry。先统一 token，再做 6 主题；高对比和色盲安全是“可读性选项”，不是第六套皮肤。

### 差距 7：交付与自动化

**现状**：`ci` 已有 JSON 和 exit code；报告有 MD/HTML；没有 JSON Schema、SARIF、GitHub Action、策略门禁、MCP/Agent 接口；桌面端没有“导出 JSON”。

**竞品证据**：japicmp/jar-analyzer/sem 都提供 MCP；diffoscope 提供 HTML/Markdown；japicmp 提供 XML/HTML/Markdown。

**方向**：把 CI 契约做成产品：Schema + 示例 + Action 模板 + `--fail-on-breaking` / `--fail-on-cve` / baseline 白名单；再提供 MCP，让 Agent 查询同一套结论。

## 5. UI 升级方案：Launchpad + Workspace 双态

### 5.1 信息架构

```text
Launchpad（首页）
├─ 新建比对：包 / 目录 / 拖拽
├─ 最近对比：状态、风险、时间、继续审阅
├─ 收藏/命名会话
├─ 模板：发布审计 / 兼容性检查 / 配置变更 / 快速 diff
└─ 示例包 + 3 步引导

Workspace（工作区）
├─ Compare Bar：老/新路径、类型、比对/停止、全局搜索、命令
├─ Left：Review Tree（文件树 / 变更列表 / 审阅队列）
├─ Center：Tabs + Filebar + Diff + Minimap
├─ Right：Insight（总览 / 兼容 / 影响 / 证据 / AI）
└─ Status：变更统计 / 审阅进度 / 后台任务 / 缩放 / 版本
```

### 5.2 顶部：从“工具栏”到“命令栏”

当前工具栏的问题不是“按钮不好看”，而是 **所有频次的动作都在同一层**。建议分三层：

1. **全局层（始终可见）**：输入类型、老/新路径（可折叠为“当前对比”摘要）、比对/停止、全局搜索、命令面板。
2. **上下文层（随视图变化）**：Diff 视图显示粒度/折叠/换行/上下一处；树视图显示过滤/排序；报告视图显示导出/模板。
3. **低频层（命令面板/更多）**：主题、强调色、配置、历史、下载、帮助、诊断包。

快捷键策略：

- 保留 `Ctrl+Enter` 比对、`Ctrl+K` 聚焦树过滤、`?` 速查。
- 命令面板用 `Ctrl+Shift+P`，避免与 `Ctrl+K` 冲突。
- 增加 `F7/F8` 上一处/下一处、`Ctrl+Shift+M` 标记已审、`Ctrl+Shift+B` 加书签（可在设置中改）。

### 5.3 左栏：Review Tree 三视图

- **文件树**：保留现有 L0/L1/L2、状态/风险/搜索过滤、右键排除/忽略。
- **变更列表**：按风险/类型/状态排序的扁平列表，适合“先看 Top 风险”。
- **审阅队列**：未审/需复核/已审三段；支持“只看未审”“跳到下一未审”。

树头增加一条 **审阅进度条**：`已审 12/48 · 高风险 3/5 · 备注 4`。它不是装饰，而是让用户随时知道“还差多少”。

### 5.4 中栏：Diff 的“可导航性”

- **Minimap**：右侧 8px 竖向地图，红/黄/绿标记增删改；点击跳转；当前视口高亮。
- **Hunk Header**：`@@ -120,7 +120,9 @@` 固定显示，附“函数/类名”上下文。
- **Sticky Breadcrumb**：滚动时文件路径与类名固定在 filebar 下方。
- **Review Gutter**：已审阅/书签/备注三态图标；点击即标记，悬浮显示备注。
- **Noise Badge**：该文件“仅格式变化/仅注释变化/成员重排”时，filebar 显示“AST 判等，已忽略 N 处”。

### 5.5 右栏：Insight 五页签

| 页签 | 内容 | 数据来源 |
|---|---|---|
| 总览 | 4 KPI、Top5 风险、类型分布、建议回归 | stats + impact + AI |
| 兼容 | 移除 API/签名变更/新增 API、语义版本建议 | `ApiCompat` 结构化 |
| 影响 | 变更类/方法 → 调用方 → 入口 → 测试 | `ImpactAnalyzer` + 未来方法图 |
| 证据 | 书签、备注、审阅记录、AST 降噪、导出 | 本地审阅状态 + 报告 |
| AI | 现有控制台，增加“解释当前 hunk”入口 | `AiConsole` |

### 5.6 响应式与可访问性

- 断点：≥1440 三栏；1280–1440 右栏 320px；1080–1280 右栏可收起；<1080 默认收起右栏。
- 高 DPI：125%/150%/200% 下工具栏不换行、图标不模糊、表格不裁切。
- 键盘：Tab 顺序 = Compare Bar → Tree → Diff → Insight → Status；Diff 行可用方向键移动，Enter 标记已审。
- 读屏：树节点 `role=treeitem`、diff 行 `aria-label` 包含“新增/删除/修改 + 行号 + 内容摘要”。
- 动效：尊重 `prefers-reduced-motion`；关闭 minimap 动画/平滑滚动。

## 6. 主题升级方案：Token + 6 主题 + 主题工作室

### 6.1 架构

```text
Theme Registry（JSON）
   └─ Semantic Tokens（--bd-*）
        ├─ Surface / Text / Border / Accent
        ├─ Diff: added / deleted / modified / moved / selected
        ├─ Syntax: kw / str / com / num / fn / type / tag / attr ...
        └─ Chart / Report / Installer
             └─ Components（Vue / CSS）
```

原则：

1. **组件只消费语义 token，不直接写 `--bs-*` 或色值。** 保留 Bootstrap 作为基础，但用 `--bd-*` 映射，迁移期双轨。
2. **UI 主题、代码语法主题、报告主题解耦。** 用户可以“暗色 UI + GitHub Light 代码 + 正式报告”。
3. **主题是数据，不是代码。** Registry JSON 可导入/导出/校验；新增主题不需要改组件。

### 6.2 主题矩阵

| 主题 | 场景 | 背景/表面 | 文本 | 差异语义 | 备注 |
|---|---|---|---|---|---|
| Light | 日常办公 | 白/浅灰 | 深灰 | 绿/红/琥珀 | 默认 |
| Dark | 夜间/低光 | 深灰 | 浅灰 | 亮绿/亮红/琥珀 | 现有 |
| System | 跟随 OS | 自动 | 自动 | 自动 | 现有 |
| Midnight | OLED/长时间 | 深蓝黑 | 蓝白 | 青/橙/紫 | 降低纯黑对比刺痛 |
| Paper | 护眼/打印预览 | 暖白 | 棕黑 | 橄榄/砖红/赭 | 低蓝光 |
| High Contrast | 无障碍/投屏 | 黑/白 | 纯白/纯黑 | 高饱和+边框 | 4.5:1 以上，焦点 3:1 |

### 6.3 色盲安全

- 提供“蓝/橙”差异色方案：added `#2F81F7`、deleted `#F0883E`、modified `#A371F7`、moved `#2DD4BF`。
- 不只靠颜色：`+` / `−` / `~` / `→` 符号；变更块左侧 3px 纹理条；当前行双层描边。
- 设置项独立于主题：`diffPalette: default | colorblind`。
- 验收：用 deuteranopia/protanopia 模拟器检查，新增/删除/修改三类可区分；对比度 ≥3:1（非文本）/4.5:1（文本）。

### 6.4 密度、字号、缩放

| 档位 | UI 字号 | 代码字号 | 行高 | 适用 |
|---|---|---|---|---|
| 紧凑 | 12px | 12px | 1.35 | 大包、审计老手 |
| 舒适 | 13px | 13px | 1.55 | 默认 |
| 演示 | 15px | 16px | 1.8 | 投屏/评审会 |

- 缩放 80%–150%，只缩放内容区，不缩放窗口 chrome。
- 字号/密度/缩放三项独立持久化；提供“恢复默认”。

### 6.5 主题工作室

- 入口：设置 → 外观 → 主题工作室。
- 能力：缩略预览、全屏预览、复制主题、导入 JSON、导出 JSON、恢复默认、删除自定义。
- 预览必须“取消即还原”（BC 5.2.2 的教训）。
- 校验：13 个语法 token + 8 个语义 token 完整性；非法值拒绝并提示。

### 6.6 报告、安装器、首屏

- 报告主题：`Screen`（跟随 App）/ `Formal`（白底、黑字、页脚页码、黑白打印可读）。
- 安装器/更新器：暗色 + 高 DPI；与 App 主题一致，但不强制跟随（安装时可能尚未有配置）。
- 首屏无闪白：Electron 启动前读取主题偏好 → 注入 `data-theme` / 背景色；CSS 首帧即目标主题；禁止“先白后黑”。

**竞品证据链**：WinMerge 2.16.51 初始 dark mode、2.16.47 VS Dark/Twilight、2.16.54.2 修暗色白闪、Color Schemes 可保存 INI；BC 5.0 暗色 + 5.2 安装器暗色 + 高 DPI/主题预览修复；delta 自动亮暗检测、20+ 样式元素；jar-analyzer 3 主题 10 风格。

## 8. 风险与边界

| 风险 | 说明 | 对策 |
|---|---|---|
| 范围膨胀 | 容易滑向“第二个 Beyond Compare” | 明确不做 3-way/文件夹同步/通用媒体矩阵；每季度复核 |
| 后端/UI 契约 | API/影响面目前是 Markdown 章节，前端解析易碎 | 先做 `FN-03` 结构化 JSON；报告与 UI 同源 |
| 主题迁移 | Bootstrap 变量与 scoped CSS 耦合深 | 双轨迁移：先 token 映射，再逐组件替换；视觉回归截图 |
| 大包内存 | 反编译 + 全量索引 + 多版本趋势可能爆内存 | 流式/分页/索引落盘；内存预算与熔断 |
| AI 幻觉 | 行级解释可能编造类名/调用关系 | 回答必须引用实体 ID/行号；无证据则拒答；评测集 |
| 不可信输入 | 恶意 class/归档可导致 DoS/路径穿越 | 解压边界、超时、沙箱、公式注入防护；安全夹具 |
| 排期 | 设计系统 + 审阅闭环同版本偏重 | Wave 1 只做“审阅驾驶舱 + token 底座”，功能纵深放 Wave 2 |
