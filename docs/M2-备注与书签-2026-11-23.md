## 一、实现范围

### 数据模型

审阅文档继续使用 `schemaVersion 1.0`，在 `files[key]` 下新增：

- `notes: [{ id, scope, hunkId, line, targetKey, oldLine, newLine, change, hunkHeader, before, after, text, tag, user, createdAt, updatedAt }]`
  - `scope` 为 `file | hunk | line`；`line` 为对齐行下标，与既有 `files[key].lines` 同口径。
  - `oldLine/newLine/before/after/hunkHeader` 是创建时的快照，后续重比对仍能生成可读证据。
- `bookmarks: [{ id, targetKey, scope, hunkId, line, oldLine, newLine, change, hunkHeader, before, after, user, createdAt }]`
  - 同一目标只保留一个书签，再次点击即取消。

Java `ReviewStatusCalculator.normalizeFile` 原本使用 `new LinkedHashMap<>(raw)` 保留未知字段；服务端 PUT/GET 对嵌套 notes/bookmarks 做了真实 round-trip 验证，无需改 Java 代码。

### 新增纯逻辑模块

`bempdiff/webui/src/lib/review_notes.js`

- `validateReviewNote`：空备注、超过 2000 字（按 Unicode code point）校验；CRLF 归一为 LF。
- `normalizeReviewNote / normalizeFileNotes`：标签白名单（风险/待确认/兼容/配置/其他）、scope 归一、旧数据容错、空正文丢弃、id 去重。
- `normalizeReviewBookmark / normalizeFileBookmarks`：targetKey 推导、同目标去重、数组/对象映射兼容。
- `upsertReviewNote / removeReviewNote / toggleReviewBookmark`：不可变更新，供 store 复用。
- `notesForTarget / bookmarkForTarget`：按 `targetKey`（`f` / `h:<id>` / `l:<row>`）命中。
- `buildEvidenceMarkdown`：单行 / Hunk / 多行证据，含文件路径、Hunk 头、旧/新行号、变更类型、变更前后摘要、备注全文。
- `buildReviewAppendix / appendReviewAppendix`：生成“证据与备注”章节；`excludeNotes:true` 时完全省略备注正文，只留计数、标签与证据元数据。
- `buildReviewJsonExport`：导出审阅 JSON，排除时删除 `notes[].text` 并标记 `exportMeta.noteTextExcluded`。

### store.js

- `saveReviewNote` / `deleteReviewNote`：复用 T06218 的 `updateReviewFileState`，80ms 防抖落盘与 localStorage 缓存路径不变；备注更新不触发 `reviewAdvanceTick`。
- `toggleReviewBookmarkState` / `isReviewBookmarked`：同目标一键切换。
- `reviewNotesOf` / `reviewBookmarksOf`：给 UI 读取规范化结果。

### DiffView.vue

- 文件栏新增备注数、书签数徽标；新增“审阅操作条”：目标显示（文件级 / Hunk # / 行 旧/新）、scope 选择、备注、书签、复制证据。
- 每个差异行 Gutter 增加：行备注、Hunk 备注（仅 Hunk 首行）、行书签；已有备注/书签以图标高亮，`title` 显示完整摘要。
- 新增 `ReviewNoteEditor.vue` 备注编辑器：
  - 纯文本 textarea（2000 上限 + 实时字数）、5 个标签、空/超长错误、`Ctrl+Enter` 保存、`Esc` 关闭；
  - 支持编辑 / 删除 / 从编辑器复制证据；
  - 备注以 Vue 插值渲染，不使用 `v-html`。
- 文件内所有备注以 chips 展示：`title` 悬浮完整正文，点击打开对应 target 的编辑器，满足“悬浮摘要、点击展开”。
- 证据复制优先使用当前选中行；无选中时复制当前 target；剪贴板不可用时回退 `textarea + execCommand`。

### DiffTree.vue

- 树文件节点显示备注数（`bi-chat-left-text` + count）与书签（`bi-bookmark-fill`），与文件栏图标一致。
- 新增“只看书签”chip：文件 / Hunk / 行级任一 bookmarks 即命中；无书签时 disabled；状态随 `bempdiff.treeReviewFilter` 持久化。
- `reviewFilter` 增加 `onlyBookmarks`，默认 `false`；清除全部与“全部”chip 同时重置。

### ReportPreview.vue 与导出

- 报告展示时动态追加“证据与备注”章节（Markdown / HTML / 下载同源），不存在备注/书签时不生成空章节。
- 顶部隐私提示：报告默认包含备注全文；提供“排除备注正文”勾选，切换后预览与导出即时更新。
- 新增“导出审阅 JSON”按钮：受同一个 `excludeNotes` 控制，排除时 JSON 不含备注正文。
- HTML 报告复用既有 `renderMarkdown + colorizeReport` 转义管线；`html_report.js` 的导入补 `.js` 扩展名，便于独立 Node 校验。

## 二、AC-12 验收

Given 选中 `src/Foo.java` 第 6 行（对齐行下标 5）的修改证据，When 点击“复制证据”，Then 剪贴板得到可直接粘贴的 Markdown：

```markdown
## 证据摘录：src/Foo.java

- **文件**：`src/Foo.java`
- **Hunk**：`@@ -6,1 +6,1 @@`
- **行号**：旧 6 / 新 6
- **变更**：修改
- **变更前**：`        return count;`
- **变更后**：`        return count + 1;`
```

真机断言：

- 含 `src/Foo.java`、`@@ -6,1 +6,1 @@`、`旧 6 / 新 6`、`变更前/变更后` 与源码摘要；
- 以 `## 证据摘录：` 开头，`**文件**` 等字段为 Markdown；
- Hunk 级证据包含 `Hunk 范围`，多行证据生成 `### 1.` / `### 2.` 小节；
- 备注正文以动态代码围栏包裹，正文中含反引号也不会截断围栏。
