## 1. 实现范围

### 1.1 后端：文件级审阅文档

新增 `ReviewStore.java`：

- 默认目录 `~/.bempdiff/reviews`，支持 `-Dbempdiff.reviewDir` 覆盖；
- jobId 白名单 `[A-Za-z0-9_-]{1,64}`，拒绝空、斜杠、反斜杠、`../escape` 与超长值，防路径穿越；
- `load` 返回 `{doc, exists, corruptBackup}`；文件不存在返回空文档，前端据此触发迁移；
- 损坏 JSON 自动改名 `.bad-yyyyMMddHHmmss` 备份，降级空文档，不阻塞工作区；
- `save` 先写同目录临时文件，再 `ATOMIC_MOVE`，不支持时降级 `REPLACE_EXISTING`；8MB 上限；
- `delete` 删除文件；同一 job 的读写由 `synchronized` 串行化。

新增 `ReviewStatusCalculator.java`：

- 文件状态四态：`unreviewed` / `in_progress` / `reviewed` / `needs_review`；
- `manualOverride=true` 优先保留手动态，不被 Hunk 聚合覆盖（AC-11）；
- 任一 Hunk `needs_review` → 文件 `needs_review`；已审 Hunk 全覆盖 → `reviewed`；部分 → `in_progress`；零 → `unreviewed`；
- `hunkTotal=0` 不自动视为全审，避免空 Hunk 文件误判已审；
- `summarize` 输出四态文件数、manualFiles、totalHunks、reviewedHunks、needsReviewHunks、filePercent、hunkPercent，O(n)；
- `normalizeDocument` 补 `schemaVersion=1.0` / jobId / user / updatedAt，并清除 `summary`、`exists`、`ok`、`corruptBackup` 等派生字段，派生数据不落盘。

`BempServer.java` 新增 `/api/review`：

| 方法 | 行为 |
|---|---|
| GET | 返回规范化文档 + `summary` + `exists` + `corruptBackup` |
| PUT | 读取 body（8MB 限），路径 jobId 强制覆盖 body.jobId，保存并返回规范化文档 + `summary` + `exists:true` + `ok:true` |
| DELETE | 删除文件，返回 `{ok:true, deleted}` |
| OPTIONS | 204 |
| 其他 | 405；非法 jobId 400 |

CORS 方法扩为 `GET,POST,PUT,DELETE,OPTIONS`，首页 API 列表补充 review 说明。

### 1.2 前端：审阅状态与迁移

- `api/client.js`：新增 `getReview` / `putReview` / `deleteReview`；请求支持 `keepalive`。
- 新增 `src/lib/review.js`：与 Java 同口径的文件/Hunk 聚合、文档规范化、摘要；`updateReviewFile` 只规范化变更文件，避免 1000 文件每次全量重算；`migrateLegacyReviews` 把 `{fileKey:[rowIndex]}` 转成 `hunkTotal:0 / hunks:{} / lines / status:in_progress / migratedFrom:'localStorage'`。
- `store.js`：
  - 新增 `review`、`reviewSummary`、`reviewLoading`、`reviewError`、`reviewSaveState`、`reviewMigration`；
  - `loadReviewForJob` 顺序：服务端文档 → window 缓存 `bempdiff.review.cache.<jobId>` → 旧 `bempdiff.reviewed` 迁移并 PUT；迁移成功删除旧 job 条目，失败保留旧数据并提示；
  - 同一 job 的并发加载共享 Promise，避免恢复会话时重复迁移/重复 toast；
  - 本地标记后同步更新 state 与 summary，80ms 防抖 PUT；`beforeunload` / `visibilitychange` 使用 keepalive 尽力落盘；
  - 新比对 `resetReview()`，DONE 后加载审阅；恢复上次会话也加载审阅。
- `DiffView.vue`：Hunk 推导、行级/Hunk 级/文件级标记全部写回 review doc；filebar 显示状态徽标、`已审 X/Y Hunk`、手动标记与手动已审按钮；左右 pane gutter 增加 Hunk 标记；已审行整段置灰。
- `DiffTree.vue`：树节点显示审阅状态小图标，标记后同帧更新。
- `StatusBar.vue`：显示 `审阅 reviewed/total · filePercent% · Hunk done/total · 需复核 n`。
- `i18n.js` / `main.css`：审阅文案与状态徽标、进度样式。

### 1.3 持久化策略

- 服务端 `reviews/{jobId}.json` 是唯一真源；localStorage 仅做断网/重启 window 缓存与旧数据迁移；
- 标记动作先改本地内存并同帧渲染，再防抖落盘，保证 AC-10 的即时反馈；
- 迁移只在「服务端无文件 + 无 window 缓存 + 有旧 localStorage」时触发，避免覆盖服务端较新文档；
- 迁移失败不回滚界面已展示的标记，保留旧 `bempdiff.reviewed` 并 warning，避免用户看到标记消失。

### 2.2 AC-10：标记后 100ms 内同步

点击未审 Hunk 的「标记整段」后 30ms 采样：

- `ms=53.4`（含 30ms 定时器等待）；
- 状态栏由 `审阅 0/1 · 0% Hunk 0/2` → `审阅 0/1 · 0% Hunk 1/2`；
- 文件徽标「未审」→「审阅中」，class `text-bg-warning`；
- 文件树审阅图标 0 → 1；
- 已审行 `.prow.reviewed` 0 → 2。

100ms 采样保持同一状态（`ms=134.5`，为 30+70ms 定时器加调度开销），说明 100ms 内状态与视觉已同步。400ms 后 API 已落盘：

```json
{"status":"in_progress","hunks":{"0":"reviewed"},"summary":{"hunkPercent":50}}
```

### 2.4 旧 localStorage 迁移

独立 Chrome profile，预置旧 key：

```json

```

- `legacyRaw: null`，旧 key 已删除；
- `cacheExists: true`，新缓存已建立；

### 2.5 DELETE 复核

最终测试数据目录改为 `release/review_ui_data/reviews` 后：

- PUT 临时 job → 文件存在；
- DELETE → `{ok:true,deleted:true}`；
- 200ms 后文件不存在，GET `exists=false`。

此前在 agent workspace 下 DELETE 返回 `deleted:true` 但文件仍在，已定位为**该工作区目录的删除回滚/同步行为**（普通 txt 删除后同样被恢复），不是 `ReviewStore` 缺陷；换到普通 release 数据目录后 DELETE 正常。该环境问题已从产品结论中排除。

## 4. 实施中发现并修复的问题

1. **空 Hunk 被误判已审**：`hunkTotal=0` 时若按“全部 Hunk 已审”会直接 `reviewed`。已改为不自动全审；旧迁移 `hunkTotal=0` 且有 `lines` 时判 `in_progress`。
2. **派生字段落盘**：早期 PUT 把 `summary`、`exists`、`ok` 写入 JSON。已在 `normalizeDocument` 清除，最终落盘文件仅剩 schema/jobId/user/updatedAt/files。
3. **恢复会话重复迁移**：`loadReviewForJob` 被并发调用时会重复读旧 key、重复 PUT、重复 toast。已用同 job Promise 共享，迁移只发生一次。
4. **DELETE 假成功**：agent workspace 目录会恢复被删文件，导致迁移测试始终走“服务端已存在”分支。已定位为测试环境目录行为，改用 `release/review_ui_data/reviews` 后 DELETE、迁移均通过。
5. **迁移后旧 key 未删**：根因同上（DELETE 未真正生效，服务端文档一直存在）。修复测试目录后 `legacyRaw=null`。
