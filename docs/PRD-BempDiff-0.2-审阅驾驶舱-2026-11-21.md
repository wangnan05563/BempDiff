本轮共评估 **58 项**优化需求，结论如下：

**一句话结论：0.2.x 不做“更多分析器”，只做“把已有能力变成可看见、可操作、可审计的产品”。**

### 0.2 五条关键决策

1. **先产品化，后继续扩能力。** `FR-001`～`FR-015` 已交付基础版；0.2.x 不再重复立项，重点是把 `ApiCompat`、`ImpactAnalyzer`、`AstNormalizer`、`Main.ci` 的结论搬进 UI 和报告。
2. **0.2.x 不做 API 兼容 2.0 / 影响面 2.0。** 只做“结构化数据 + 面板显性化”；二进制级 API、方法级调用图放 0.3.x，避免半成品。
3. **主题先做 Token，再做 6 主题。** 不允许在现有组件上继续叠硬编码色值；先统一语义 token，再上高对比、色盲、午夜、护眼。
4. **审阅数据本地优先、可导出、不做多人协作。** 0.2.x 的“审计”是单机证据链：文件级进度、备注、书签、JSON 导出、报告附录；不引入账号/云端。
5. **安全是 0.2.x 的发布门禁。** 恶意归档、解压炸弹、反编译超时、HTML/CSV 注入必须过恶意夹具；不过门禁不发版。

## 1. 背景与问题

### 1.1 当前产品基线

BempDiff 是面向 Java 交付物（war/jar/zip/文件夹）的桌面差异化对比与智能分析工具。当前已具备：

- 递归解包、L0/L1/L2 分层差异树、CFR 反编译、AST 归一化、行/词/字符级 diff。
- API 兼容性静态分级、类级影响面、CI `--json --fail-on-diff`、Markdown/HTML 报告。
- 三栏工作区、多 tab、树筛选、逐 hunk 已审阅、4 套语法主题、亮/暗/跟随系统 + 6 强调色。
- 两阶段 AI、风险分类、成本闸门、流式控制台。

**问题不是“没有能力”，而是“能力没有被组织成一条用户可完成的任务链”。**

### 1.2 三个核心问题

| 问题 | 现状证据 | 用户后果 |
|---|---|---|
| 入口重、首屏没有“任务感” | 打开即进入工作区；路径输入、历史、会话挤在顶部工具栏；无首页/最近/模板 | 新用户不知道从哪开始；老用户重复找路径 |
| 审阅断点多 | 只有逐 hunk 标记；无文件级汇总、未审筛选、备注、审计导出 | 审到一半不知道还差多少；审完无法交差 |
| 强结论不可见 | API 兼容/影响面/AST 降噪只在报告章节；CI JSON 无文档/模板 | 用户要翻报告才知道风险；研发无法据此排期 |

### 1.3 为什么是现在

- 当前发布 `0.1.2026111703` 已把“比对 + AI + 报告”跑通，继续堆后端能力的边际收益下降。
- 竞品已把“审阅状态、总览、主题系统、CLI/Agent 接口”做成产品基线；BempDiff 的差异化在“构建包审计”，不在“通用 diff 广度”。
- 现有代码已具备 0.2.x 所需的 80% 数据基础：`ApiCompat`、`ImpactAnalyzer`、`AstNormalizer`、`reviewedMarks`、`ci` 均可复用。

## 2. 产品目标与非目标

### 2.1 产品目标

把 BempDiff 从“能比对”升级为 **“能审阅、能解释、能交付”**：

1. **可开始**：新用户 3 分钟内从启动台完成一次比对并生成报告。
2. **可审阅**：任意时刻知道“已审多少、还剩多少、风险在哪、下一处去哪”。
3. **可解释**：API 兼容、影响面、AST 降噪在同一界面可查、可跳转、可引用。
4. **可交付**：报告带审阅记录/证据，可离线归档；屏幕阅读可读。
5. **可信任**：恶意归档不越界、不挂死、不注入。

### 2.2 非目标

- 不做通用 diff/merge 工具，不与 Beyond Compare 拼查看器矩阵。
- 不做云端协作/账号体系/多人实时审阅。
- 不在 0.2.x 做二进制级 API 兼容、方法级调用图、SBOM/CVE。
- 不改变 Java 核心 diff 算法、AI 厂商协议、CLI 既有参数语义。

### 2.3 约束

| 约束 | 说明 |
|---|---|
| 技术栈 | Electron 壳 + Vue 3 + Bootstrap 5.3 + Java 21 sidecar |
| 输入模式 | “包 / 目录”保持两个独立入口，不做自动识别/合并 |
| 快捷键 | `Ctrl+K` 保留给树过滤；完整命令面板（0.3.x）用 `Ctrl+Shift+P` |
| 数据边界 | API Key 不落盘；审阅数据默认本地；不默认上传遥测 |
| 兼容 | 0.2.x 以 Windows x64 为主；macOS/Linux 走 CI 产物，不阻塞首发 |
| 版本 | 0.2.x 内不做破坏性 API/CLI 变更；新增字段一律增量 |

## 6. 信息架构与核心流程

### 6.1 双态结构

```text
Launchpad（首页）                  Workspace（工作区）
├─ 新建：包 / 目录 / 拖拽          ├─ Compare Bar
├─ 最近：继续审阅 / 查看报告        ├─ Left：Review Tree
├─ 收藏 / 命名会话                 ├─ Center：Tabs + Diff
├─ 模板：发布审计/兼容/配置/快速    ├─ Right：Insight 五页签
└─ 示例包 + 3 步引导               └─ Status：统计/审阅/任务/缩放
```

### 6.2 主流程

1. **开始**：Launchpad 选择“新建比对”或“最近任务” → 进入 Workspace。
2. **预检**：路径/包有效性/大小/同输入检查 → 通过后开始比对。
3. **总览**：任务完成后默认打开“总览”页签，展示 KPI/Top 风险/类型分布。
4. **审阅**：左树筛选“未审” → 中栏逐文件 diff → 标记已审/加备注/书签 → 自动跳下一未审。
5. **解释**：右栏“兼容/影响”查看证据 → 点击跳到具体文件/类/行；AI 页签查看现有任务级分析（行级追问在 0.5.x / AU-04）。
6. **交付**：导出 Markdown/HTML 报告（附审阅记录与证据）；报告模板/PDF/JSON 分享包在后续版本。
7. **CI（可选）**：同一 job 结论通过现有 `ci --json` 输出；完整 JSON/SARIF 契约在 0.3.x（AU-01）。

### 6.3 导航层级

- **全局层**：输入类型、当前对比摘要、比对/停止、全局搜索、更多菜单。
- **上下文层**：Diff（粒度/折叠/换行/上下一处）、树（过滤/排序/视图）、报告（导出/审阅记录）。
- **低频层**：主题/强调色/配置/历史/下载/帮助/诊断包 → “更多”菜单。

## 7. 功能需求

### 7.1 Epic A：启动台与工作区

#### A1（CX-01）Launchpad

**用户故事**：作为发布经理，我希望打开应用就看到最近对比和未审项，而不是先找路径输入框。

**需求描述**：

- 应用启动默认进入 Launchpad；用户可从“新建比对”直接进入 Workspace。
- 卡片区：
  - 新建：包对比、目录对比、拖拽提示。
  - 最近：最近 10 条对比，显示时间、模式、文件数、风险数、审阅进度、报告状态。
  - 收藏：用户 pin 的会话/对比。
  - 模板：发布审计、兼容性检查、配置变更、快速 diff（启动预设：路径/过滤/面板，不含报告模板）。
  - 示例包：内置小样本，3 步引导。

### 7.2 Epic B：审阅闭环

#### B1（CX-02）文件级审阅状态

**用户故事**：作为审计人员，我需要知道每个文件是否审过、还差多少、哪些需要复核。

**状态模型**：

- `unreviewed`：未审。
- `in_progress`：部分 hunk 已审，尚未完成。
- `reviewed`：已审。
- `needs_review`：需复核（例如有备注待确认、AI 高风险未处理）。
- 文件级状态由 hunk 标记聚合：全部 hunk 已审 → `reviewed`；部分 → `in_progress`；手动“需复核”覆盖聚合。
- 用户可手动设置文件状态；切换文件保留。

**需求描述**：

- 树/列表/状态栏显示进度；筛选“未审/需复核/已审”。
- 快捷键 `Ctrl+Shift+M` 标记当前文件/当前 hunk（取决于焦点）。
- 数据持久化：应用数据目录下 `reviews/{jobId}.json`（跨重启/临时目录清理仍保留）+ `localStorage` 缓存；localStorage 旧数据自动迁移。
- 报告：新增“审阅记录”章节：文件、状态、备注数、最后更新时间、审阅人（本地显示名，`BEMPDIFF_REVIEWER` 可覆盖）；报告与界面同源。
- 导出：`review.json` 可随报告/任务导出；schema 版本化。

**验收标准**：

1. 标记后 100ms 内更新树/状态栏/总览。
2. 关闭应用再打开，审阅状态不丢；迁移失败保留旧数据并提示。
3. “只看未审”可一键切换；标记后自动跳下一未审（可关闭）。
4. 报告“审阅记录”与界面 100% 一致。
5. 文件级手动覆盖与 hunk 聚合冲突时，以手动为准并显示“手动标记”。
6. 1000 文件任务下，进度计算 <200ms。

**验收标准**：

1. 任意 hunk/行可加备注；悬浮显示摘要，点击展开。
2. 书签跨会话保留；树/文件栏图标一致。

#### B3（CX-04）总览先行

**用户故事**：作为发布经理，我希望打开任务先看到“这次变更有多大、最危险的是什么、先看哪 5 个文件”。

**总览内容**：

#### C3（FN-04）配置语义 diff

**用户故事**：作为发布经理，我不希望 `application-prod.yml` 只是“整行变了”，我要知道哪个 key、什么类型、影响哪个环境。

**支持格式**：

- `.properties`：key=value、重复 key、编码。
- `.yaml/.yml`：嵌套 key、数组、锚点/别名（只解析，不执行）。
- `.xml`：元素/属性/文本、命名空间。
- `.json`：对象/数组/类型。
- 0.2.x 不含 `.xlsx/.docx` 单元格级（FN-05 放 0.3.x）。

**规则**：

- 按键路径对齐（`spring.datasource.url`），忽略 key 顺序/缩进/注释。
- 变更类型：added/deleted/modified/type-changed/order-only/duplicate-key。
- 值展示：字符串、数字、布尔、null、数组长度；长值截断可展开。
- 密钥脱敏：key 命中 `password/secret/token/key/credential` 等模式时，值默认 `***`；用户可临时显示（本地）。
- 环境占位符（`${...}`）单独标记，不判为实质变更。
- XML：按元素路径 + 属性名对齐；命名空间前缀归一；拒绝 DOCTYPE/外部实体；不执行 XPath。
- YAML：锚点/别名只解析不执行；数组按索引/长度展示，不展开为无限结构。
- UI：树按文件 → 配置组 → key；中栏 key-level 表格；可复制 key/value。
- 报告：配置变更章节，按文件/键路径列出。

**验收标准**：

1. 5 类夹具（properties/YAML/XML/JSON/混合）键路径对齐准确率 100%（人工标注）。
2. 仅 key 顺序/缩进/注释变化不产生差异。
3. 类型变化（字符串→数字/布尔）单独标记。
4. 密钥值默认脱敏；报告/导出不含明文（除非用户显式选择）。
5. 1000 key 文件渲染 ≤500ms；可搜索/筛选。
6. 解析失败降级为文本 diff，并提示失败原因。
7. XML 属性/命名空间变更可对齐；XXE/实体膨胀被拒绝；XPath 不作为输入执行。

### 7.5 Epic E：安全与质量

#### E1（NF-02）安全加固

**威胁模型**：不可信 jar/war/zip/目录、恶意 class、恶意配置、导出注入。

**需求**：

- 归档：路径穿越（`../`）、绝对路径、符号链接、解压炸弹（压缩比/总大小/条目数/嵌套深度）、临时目录清理。
- 反编译：单类/单文件超时、总 CPU/内存上限、输出大小上限、失败降级、不执行 class。
- 解析：XML 外部实体（XXE）禁用、YAML 安全加载、JSON 深度限制。
- 导出：HTML 转义、Markdown 转义、CSV 公式注入（`= + - @` 前缀）、路径不泄露。
- 日志：不记录 API Key/密钥值；诊断包脱敏。

**验收标准**：

1. zip slip 夹具不写出目标目录；无残留临时文件。
2. 解压炸弹夹具在阈值内终止并提示；不 OOM。
3. 恶意 class 夹具不执行代码；反编译超时后降级/跳过。
4. XXE/YAML 反序列化夹具不读取本地文件/不执行。
5. CSV 导出公式注入被转义；HTML 报告无 XSS。
6. 100 次恶意夹具连续跑，进程不崩、内存不持续增长。

## 9. 主题规范

### 9.1 Token 清单（最小集）

```text
surface: canvas / surface / elevated / overlay
text: primary / secondary / muted / inverse
border: subtle / strong / focus
accent: default / hover / active / subtle
status: success / warning / danger / info
diff: added-bg/fg/border / deleted / modified / moved / selected
syntax: keyword / string / comment / number / function / type / tag / attr / regex / operator
report: page / header / footer / table / code
```

### 9.2 主题切换顺序

1. 读取偏好（Registry id + modifiers）。
2. 校验 token；失败回退 Light。
3. 注入 `data-theme` 与 CSS 变量。
4. 通知组件（避免逐组件重排）。
5. 持久化；System 监听 `prefers-color-scheme`。

### 9.3 密度/字号/缩放（0.3.x / TH-05；0.2.x 默认舒适档）

> 0.2.x 只交付默认舒适档（UI 13px / 代码 13px / 行高 1.55）；紧凑/演示/80–150% 缩放在 0.3.x（TH-05）。

- 紧凑：UI 12px / 代码 12px / 行高 1.35。
- 舒适：13px / 13px / 1.55（默认）。
- 演示：15px / 16px / 1.8。
- 缩放 80%–150%；只缩放内容区；持久化。

### 9.4 主题工作室（0.3.x / TH-04；0.2.x 只做切换与缩略预览）

- 0.2.x：设置页提供主题下拉/缩略预览、色盲/密度开关；不开放自定义导入。
- 0.3.x：缩略预览 + 全屏预览；取消即还原；复制/导入/导出/删除/恢复默认。
- JSON Schema 校验；禁止 CSS/JS 注入；只允许 token 值。
- 自定义主题标注“本地”，不自动上传。

### 9.5 报告/打印/安装器

- 报告主题：0.2.x 沿用现有报告样式；`Formal` 打印主题在 0.3.x（TH-07）交付。
- 安装器/更新器：Backlog（TH-08）；0.2.x 只保证首屏无闪白（TH-09）。
- 首屏：无闪白；System 跟随。

## 10. 数据与接口契约

### 10.1 Job 摘要（增量）

```json
{
  "schemaVersion": "1.0",
  "jobId": "job-...",
  "status": "DONE",
  "stats": {"added": 3, "deleted": 1, "modified": 12, "files": 48},
  "apiCompat": {"level": "WARNING", "summary": {"breaking": 1, "warning": 2, "additive": 3}, "items": []},
  "impact": {"risk": "HIGH", "items": []},
  "astSummary": {"normalizedFiles": 5, "fallbackFiles": 1, "ignoredChanges": 12},
  "reviewSummary": {"total": 48, "reviewed": 12, "inProgress": 3, "needsReview": 3, "notes": 4, "bookmarks": 2}
}
```

### 10.2 Review 状态

```json
{
  "schemaVersion": "1.0",
  "jobId": "job-...",
  "updatedAt": "2026-11-21T14:00:00+08:00",
  "user": "local-display-name",
  "files": {
    "BOOT-INF/classes/com/acme/Foo.class": {
      "status": "reviewed",
      "manualOverride": false,
      "hunks": {"0": "reviewed", "1": "reviewed"},
      "notes": [{"id": "n1", "scope": "hunk", "hunk": 1, "text": "...", "tag": "risk", "at": "..."}],
      "bookmarks": [{"id": "b1", "line": 42, "label": "重点", "at": "..."}]
    }
  }
}
```

### 10.3 API 兼容结构

> 0.2.x 后端仍是源码级 public/protected 判断；`binaryImpact` 允许 `UNKNOWN`，不得伪造。0.3.x（FN-01）补齐二进制级/语义版本。

```json
{
  "level": "BREAKING",
  "items": [{
    "kind": "method-removed",
    "className": "com.acme.Foo",
    "memberName": "bar",
    "signature": "(Ljava/lang/String;)V",
    "binaryImpact": "BREAKING",
    "sourceImpact": "BREAKING",
    "evidence": ["Foo.java:120"],
    "confidence": "deterministic"
  }]
}
```

### 10.4 影响面结构

> 0.2.x 只填充类级 `callers/evidence`；`entries/tests` 可为空，前端显示“未提供”。0.3.x（FN-02）补齐方法级/入口/测试。

```json
{
  "risk": "HIGH",
  "items": [{
    "changedClass": "com.acme.Foo",
    "callers": [{"className": "com.acme.Bar", "method": null, "line": null}],
    "entries": [],
    "tests": [],
    "confidence": "static",
    "evidence": ["Bar.java:42"]
  }]
}
```

### 10.5 CI JSON 契约

- `schemaVersion`、`jobId`、`left`、`right`、`stats`、`apiCompat`、`impact`、`report`、`exitCode`。
- 退出码：`0` 无差异/通过；`1` 有差异/命中 fail 条件；`2` 执行错误。
- 0.2.x 不改既有字段；0.3.x 增加 Schema/SARIF（AU-01）；0.4.x 增加 `--fail-on-breaking`、`--fail-on-cve`（AU-02）。
- 桌面/CI 结论一致率 100% 为 0.3.x 目标；0.2.x 先保证报告/UI 同源。

### 10.6 契约原则

- 所有新增字段可选；前端缺失降级。
- 枚举值大小写固定；新增枚举只增不改。
- 报告不解析 UI 内部结构；报告/UI/CI 同源。
- Schema 变更必须带版本与迁移说明。

## 11. 非功能需求

### 11.1 性能

| 场景 | 目标 | 备注 |
|---|---|---|
| 50k 树首屏 | ≤2s | 虚拟滚动；首屏只渲染可见 |
| 10k 行 diff 滚动 | ≥50fps | 窗口化；避免整容器重排 |
| 200MB 包对比 | ≤30s | 与现有基线一致 |
| 1000 文件审阅进度 | <200ms | 增量计算 |
| 配置 1000 key | ≤500ms | 虚拟列表 |
| 主题切换 | ≤200ms | 不重排全树 |
| 内存 | 200MB 包 ≤2GB | 超限提示/降级 |

### 11.2 安全

- 不可信归档/class/配置按 E1 处理。
- API Key 不落盘；日志/诊断包脱敏。
- 报告 HTML 转义；Markdown/CSV 注入防护。
- 本地 HTTP 仅监听 `127.0.0.1`；无远程暴露。
- 依赖升级走安全审计；不引入未知二进制。

### 11.3 可靠性

- 崩溃恢复：最近任务/审阅状态/窗口布局。
- 导出原子写：临时文件 + rename；失败不覆盖旧报告。
- 任务取消：比对/解包/AI/导出可取消；取消后清理临时文件。
- 错误可诊断：错误码 + 诊断包入口。

### 11.4 兼容性

- Windows 10/11 x64 首发；125/150/200% DPI。
- Electron 当前版本；WebView 不单独支持。
- macOS/Linux 走 CI 产物；不阻塞 0.2.x 首发。
- 旧 `localStorage` 审阅标记迁移；旧报告格式继续可读。

### 11.5 隐私与可观测性

- 默认不上传遥测；本地记录关键事件（启动、比对耗时、导出、错误码）。
- 用户可导出诊断包；不含 API Key/密钥值/完整路径（可配置脱敏）。
- AI 请求前脱敏；成本闸门生效。

### 11.6 可维护性

- 新增代码模块化：`review/`、`theme/`、`launchpad/`、`config-diff/`。
- 组件只消费 token；禁止新增硬编码色值。
- 需求 ID 与测试用例双向追溯；PR 关联 ID。

### 16.1 术语

| 术语 | 含义 |
|---|---|
| Hunk | diff 中一个连续变更块 |
| 文件级审阅 | 由 hunk 状态聚合 + 手动覆盖得到的文件状态 |
| AST 归一化 | 忽略格式/注释/成员重排的等价判定 |
| API 兼容分级 | 移除 API / 签名变更 / 新增 API 三级（0.2.x 仅源码级） |
| 影响面 | 变更类被哪些类/入口/测试引用（0.2.x 为类级静态） |
| Token | 语义化设计变量，如 `--bd-diff-added-bg` |
| Registry | 主题注册表，定义主题与 token 映射 |
| Preflight | 比对前检查 |
