# 构建产物与清理（release 目录约定）

> 自 2026-11-16 起，BempDiff 把**全部可重复构建的产物**集中到仓库根 `release/`。
> 清理磁盘只需删这一个目录，git 仓库保持干净；下次构建时脚本会按需重建。
> 本文说明「哪些在 release 里、哪些故意不在、如何重建、如何清理」。

## 1. 目录映射

| 产物 | 原位置 | 现位置 | 生产者 |
|---|---|---|---|
| 打包输入（app / classes / jre / webui） | `bempdiff/dist_input/` | `release/dist_input/` | `bempdiff/scripts/build_dist_input.ps1` |
| 前端构建产物 | `bempdiff/webui/dist/` | `release/webui/dist/` | `bempdiff/webui` → `npm run build`（Vite `build.outDir`） |
| Java 核心编译产物 | `bempdiff/java_core/out/` | `release/java_core/out/` | `bempdiff/java_core/build_and_test.sh`、`tooling/scripts/quality/build_and_test.ps1` |
| Java 测试编译产物 | `bempdiff/java_core/test_out/` | `release/java_core/test_out/` | 同上 |
| JaCoCo 覆盖率 | `tooling/quality/jacoco/jacoco.exec|xml` | `release/quality/jacoco/` | `tooling/quality/jacoco/run_coverage.ps1` |
| AI 报告编译 class | `tooling/scripts/dev/ai_report/out/` | `release/ai-report/out/` | 报告生成脚本 |
| 反编译 / 端到端临时产物 | `bempdiff/artifacts/` | `release/artifacts/` | `decompile` / `e2e` 相关脚本 |
| 原生命令编译日志 | `bempdiff/build_native.log` | `release/logs/build_native.log` | `build_dist_input.ps1` |
| JMeter 运行日志 | `jmeter.log`（仓库根） | `release/logs/jmeter.log` | `run_perf.ps1` / JMeter |
| Python 字节码缓存 | 各 `__pycache__/` | `release/cache/pycache/` | 各 Python 脚本 |
| Vite 临时配置副本 | `bempdiff/webui/vitest.config.js.timestamp-*.mjs` | `release/cache/webui/` | Vitest |
| 开发态临时 class（`_testcls`） | `bempdiff/scripts/_testcls/` | `release/cache/_testcls/` | `_run_model_test.ps1`、`test_p0_backend.ps1` |
| 安装包 / win-unpacked / 构建临时目录 | `release/`（本来就在） | `release/`（不变） | `构建打包.bat`、electron-builder |

`release/` 已在 `.gitignore` 第 32 行忽略；`git status` 不会出现其中任何文件。

## 2. 为什么这些**不**搬

以下内容属于「重建前提」或「已入库证据」，搬走会导致构建失败或 git 出现删除记录，因此保持原位：

- `bempdiff/toolchain/`（约 340MB JDK）：编译与 jlink 的工具链，`lib/*.jar` 已入库。
- `bempdiff/cfr.jar`、`bempdiff/lib_v1.jar` / `lib_v2.jar`：编译 / 测试 / 演示的输入。
- `bempdiff/node_modules/`、`bempdiff/dev-shell/node_modules/`、`bempdiff/webui/node_modules/`：依赖，重建需联网安装。
- `tooling/jmeter/results/`（177 个跟踪文件，约 80MB）：性能证据，`.jtl.gz` 实测在库。
- `bempdiff/verify_exe/`、`tooling/verify_exe/`、`bempdiff/java_core_export/`、`bempdiff/java_core_ai_replay/`、`bempdiff/java_core/e2e_work/`：已入库证据 / 夹具。
- `bempdiff/assets/`、`bempdiff/build/`（electron-builder buildResources，`installer.nsh` 是源码）。
- `bempdiff/logs/`：桌面壳运行时日志目录（`dev-shell/main.js` 的 `LOGDIR`），不是构建产物。
- `bempdiff/fixtures/`：压测夹具目录（当前为空）。

## 3. 路径约定

- **开发态**（`node tooling/scripts/启动服务.bat`、直接跑 `java -cp ...`）统一读 `release/` 下的产物。
- **打包态**保持 electron-builder 的落地路径不变：安装包内仍是
  `resources/bempdiff/dist_input/{app,jre,webui}`。`bempdiff/package.json` 的
  `extraResources.from` 指向 `../release/dist_input/*`，`to` 不变，因此安装包结构与旧版一致。
- CI 两个工作流（`.github/workflows/build-arm64.yml`、`build-arm64-unix.yml`）已同步：
  JRE 就位、`javac -d`、`jar cfe`、webui 镜像全部写 `release/dist_input`；
  安装包内路径校验仍指向 `resources/bempdiff/dist_input`，无需改动。

## 4. 重建

| 想重建什么 | 命令（仓库根执行） |
|---|---|
| 全部打包输入（Java jar + jlink JRE + 前端 + 镜像） | `bempdiff/scripts/build_dist_input.ps1`（加 `-Clean` 先清空） |
| 仅前端 | `cd bempdiff/webui && npm run build` → `release/webui/dist` |
| 仅 Java 编译 + 测试 | `bempdiff/java_core/build_and_test.sh`（Windows 可用 `tooling/scripts/quality/build_and_test.ps1`） |
| 覆盖率报告 | `tooling/quality/jacoco/run_coverage.ps1` → `release/quality/jacoco/` |
| 一键打包（含以上全部） | `tooling/scripts/构建打包.bat` |
| 性能压测前置 | `tooling/scripts/perf/run_perf.ps1 -Build` |

## 5. 清理

推荐两种方式（等价）：

```powershell
# 方式一：直接删目录
Remove-Item -LiteralPath .\release -Recurse -Force

# 方式二：带安全检查与体积统计（推荐）
tooling/scripts/clean-release.ps1 -DryRun    # 先看会删多少
tooling/scripts/clean-release.ps1 -Force     # 真正删除
tooling/scripts/清理构建产物.bat              # 双击即删（内部调用 -Force）
```

`clean-release.ps1` 的保护措施：

1. 只接受 `<仓库根>\release` 这一精确路径，仓库根以 `bempdiff/package.json` 为标记；
2. 默认演练，必须 `-Force` 才删除；
3. 若检测到 `java/javaw` 进程的可执行文件位于 `release/` 内，先报 PID 并拒绝删除（避免 JRE 被占用）；
4. 删除只在本进程内完成（`Remove-Item` → `.NET Directory.Delete` 回退），不转交其他 shell。

删除后 `release/` 不再存在属于正常状态；下次 `build_dist_input.ps1` / `npm run build` /
`构建打包.bat` 会自动重建所需子目录。
